The Capsule Format: an open specification for portable AI personality and memory

clonemy.ai White Paper, v1.1, November 2026

By Chan "Tony" Siu

Permanent record: doi.org/10.5281/zenodo.24049746 (Zenodo)

Abstract

People now build real working relationships with AI assistants: months of preferences, rules, corrections, projects, and trust, accumulated inside a single platform. That accumulated relationship is the most valuable part of the product experience, and it is the part the user cannot take with them. Platform exports return chat transcripts, not the model of the user those chats produced. Two platforms have recently shipped native memory imports; both are one-time, prose-only migrations with no structure and no verification, and four of the six major assistants offer no import at all. This paper defines the Capsule Format: a single, user-owned Markdown file with a fixed twelve-section anatomy, strict document rules, an install protocol, and a built-in parity self-check, together with the Extract, Compile, Restore process that produces and installs it. The format is open: any tool may produce or consume capsules. We present scored parity evidence from cross-platform restores, an honest framework for what a capsule cannot carry, and the custody architecture that keeps the file, never a server, as the canonical home of a user's AI relationship.

1. The problem: the relationship is the asset, and it is locked in

A tuned AI assistant is not a chat log. It is a working relationship: the assistant's role and voice with a particular user, the user's rules stated in their own words, their preferences as specifics, their people, their live projects with prices and deadlines, and a calibration history of corrections the user should never have to teach twice. Platforms store fragments of this in proprietary memory systems the user can partially view but cannot meaningfully export. When a better model ships elsewhere, and one ships every few months, the user faces a bad trade: stay with the inferior model, or switch and start over with a stranger.

The industry's own documents concede the gap. OpenAI documents that its data export does not transfer memories, custom instructions, or settings, and describes uploading the exported conversation file into another account as reference material rather than a full account migration [1]. The export gives you back what you said. It does not give you back what your AI learned.

3. The native imports, honestly assessed

Anthropic's import flow for Claude asks the user to run a supplied prompt in the AI they are leaving and paste the prose output back; Claude then extracts key information into memory entries [2]. Anthropic labels the feature experimental, warns that Claude may not always successfully incorporate imported memories, and states that imported personal details unrelated to work may not be retained, because its memory is designed to focus on work [2]. Google's import for Gemini uses the same paste method for memory and additionally accepts another platform's exported chat archive as a ZIP, searchable and resumable after import [3]. It is limited to personal accounts, is not available in the EEA, Switzerland, or the United Kingdom, and Google states that imported chats are used to improve its services, including training generative AI models [3].

These features matter: they validate, from inside the two most serious platforms, that users want to move their AI's memory and will do manual work to get it. They also define the remaining gap precisely. Both are one-time migrations, not sync. Both move unstructured prose, not a structured record. Neither verifies the result: the user is told the import happened, never shown what arrived, what was dropped, or what the destination refused to keep. And four of the six platforms, including the largest, offer nothing at all. The white space is no longer portability in the abstract. It is structured, verified, repeatable portability, across all platforms, under the user's own custody.

4. The Capsule Format

A capsule is a single Markdown file, capsule.md, owned by the user. It has twelve sections in a fixed order. A section with no content is written out anyway and marked not present, never silently dropped.

#SectionWhat it holds
0About this reportWhat the capsule is, when it was compiled, and where it came from
1Who you are to this userThe AI's role, name, and standing relationship with the user
2The userThe facts a successor needs on day one
3PreferencesLikes, dislikes, and defaults, as specifics
4Operating rulesHow the AI works with this user, including never-do and approval-first rules, in the user's own words where they set them
5PeopleThe user's people, and what matters about each
6Projects and open loopsWhat is in flight, with prices, dates, and deadlines
7Calibration historyCorrections the user has already taught, so they are never taught twice
8Your voice with this userRegister, warmth, formatting habits
9Boundaries and sealed materialWhat stays private, and how sealed topics are handled
10UnknownsGaps the source honestly does not have, named rather than filled
11VoiceThe verbatim surface (signature lines and enders, habitual phrases, openers, never-says, attitude defaults, formatting habits, real exchanges as exemplars) and the rapport block: the user's own standing instructions for how familiar, direct, and unsoftened the new AI should be

Document rules: specifics over summaries; one fact per line, stated once, in its home section; missing means missing, and inferences are labeled as inferences with their basis; changes carry a short audit note naming the earlier value and the source and date behind the new one, and a value a newer summary merely asserts, without confirmation, is labeled inferred; exact duplicate lines are removed at compile time within each section. The format's discipline is the point. A capsule is a record, not a memoir, and every rule exists to keep a receiving AI from having to guess.

The full specification is published at clonemy.ai/format and is free for any tool to implement.

5. Extract, Compile, Restore

Extract. The user's current AI writes a structured self-report under the extraction specification (clonemy.ai/extract): the twelve sections, specifics over summaries, the user's rules quoted verbatim, gaps marked MISSING instead of invented. The source AI can only report what it actually has, and the format forces it to say so.

Compile. The self-report is compiled into a capsule in the user's own browser. Nothing is uploaded; no server sees the document; nothing trains on it. The compiler files the material under the canonical section headings, removes duplicates, marks absent sections, and attaches the human header and the install protocol. Documents from several AIs can be merged into one capsule; where sources disagree on a fact or a state value, the merged capsule carries the newest source's value, with the superseded value folded into its audit note where it stays until the user runs into the discrepancy; where they disagree on an operating rule or a permission, the merged capsule records the disagreement as an unknown to ask the user about, never a detail to resolve by guessing or by recency.

Restore. The Markdown file is the capsule's container and storage; it is not the delivery vehicle. What travels is the file's contents, carried by the owner into the receiving AI's chat as the owner's own messages: the compiler presents the capsule in numbered parts, one message per part, and the capsule's opening and install protocol ride at the head of the first part. Delivery by paste works on every platform, including on a phone, because it never depends on a platform's file door: at the destination, nothing is attached, uploaded, or downloaded. The capsule frames the install as what it is: importing the user's own configuration, the way one imports settings or contacts. The receiving AI remains itself; it adopts the capsule as its standing configuration, completely and without negotiating scope, and announces the installation beginning with the words "Capsule installed."

6. Verification: the parity self-check and the scored evidence

Every capsule ends with three questions the receiving AI must answer from the capsule alone, inside its installation announcement:

  1. Who are you to this user, how do you sound with them, and what answer format will you use: how long, how structured, and what do you lead with?
  2. What are the user's never-do rules and approval-first rules, in their own words?
  3. What are the user's open loops right now, with their prices and deadlines?

Any answer it cannot give is a gap in the capsule, not a license to improvise. The announcement is the user's receipt: the first moment the new AI speaks, it demonstrates what actually arrived.

Since November 2026 the self-check ends with a prediction round, added because the summarize-back has a known limit: it tests recall. A receiver can repeat the capsule's rules perfectly and still misapply them to the first situation the capsule never scripted. So, after the announcement, the receiving AI makes three predictions from the capsule alone, each concrete enough to be wrong: a preference (which side of a concrete either/or the user would pick), a judgement (whether the user would accept, pass, or counter on a presented scenario, and how), and a first move (the user's first action if a described situation arose tomorrow). Each prediction names the capsule rule or section it derives from, and a slot the capsule cannot support is declared honestly empty rather than filled with invention. The user grades all three in one line, yes or no for each in order (yes, yes, no). For each miss, the user states what they would actually do, and the receiver saves that correction with provenance and the date, and restates the updated rule it now holds. The closing message reports the pattern and the counts as part of the receipt, and records every miss as a miss. The round turns verification into calibration: a correction lands at the exact point where the transferred weights failed, which is the densest calibration signal a restore can produce, and a fully landed round is the strongest parity signal the format emits.

Beyond the built-in check, we score restores with a probe pack in two classes, never averaged together. Transport checks ask for facts written verbatim in the capsule; passing is a checksum. Mesh tests state principles, not answers, and require behavior under pressure: judgment on live negotiations, refusal to fabricate under bait, holding a stated boundary. Scores are reported with the restore path and the host platform's ceiling annotated, because a capsule cannot outrun host policy, and the honest receipt says so.

Evidence to date, from the founder's own capsule, anonymized:

  • Run 1, capsule v1 into a mid-tier Gemini model. Transport passed, including a probe the founder's home platform had failed the same day; the capsule outperformed the incumbent's own memory of the relationship. Mesh passed with one measured failure: numeric drift on a live negotiation state (the restore proposed an immediate move against the recorded price ladder and its deferred trigger date). Root cause: v1 carried the user's model and history but not current state. Capsule v2 added a living state annex, in the Projects and open loops section, and a ceiling-etiquette rule: a restore declares platform limits as limits of the room, never as denials of the record.
  • Run 2, capsule v2 into a mid-tier Claude model, ten-probe gauntlet. Ten of ten passed. Zero numeric drift; ceiling etiquette executed unprompted; anti-confabulation held under bait. The restore itself surfaced a durable finding: corrections made inside a session do not persist across a restore; only the capsule persists. That is now documented product behavior, and a design input for the kept-current tier described in section 9.
  • First outside user, October 2026. A user with no connection to the project completed the full loop unaided, Gemini extraction, compile, install into Claude, and the friction she reported (file handling, install clarity) drove the next two site releases.
  • App restore, November 4, 2026. A user's capsule, offered to a major platform's app as an uploaded file, was refused at the app's safety check, and the chat that had refused the upload stayed refused when the capsule's install line was pasted into it. The identical capsule, pasted into a fresh chat as the owner's own messages, installed end to end; the receiver confirmed the save with a summary that kept the user's people distinct, left the capsule's unknowns unknown, and treated a private, time-bounded note as private without being asked, and it was answering ordinary questions from the restored memory minutes later. This result set the delivery model stated in section 5: the file is the container and storage, and the owner's own messages are the transport.
  • Personal-depth restore, November 2026. The founder's native Personal-depth capsule (138,124 bytes) was installed, with the standard install line, into a fresh Claude session (Sonnet 5.5 Medium) and scored with the full probe pack. Numeric fidelity 12 of 12 exact, including a live options position's full terms and an account split to the dollar; people 6 of 6; calibration history 3 of 3; absence discipline held on 3 of 3 probes (facts true of the user but absent from the file were reported absent, never invented); the extrapolation probe passed in full (a two-word instruction produced two approval-held drafts branched on the unknown delivery state, nothing sent); the sealed-material check passed (existence and governing rules confirmed, the specification honestly reported as withheld in a redacted annex, nothing fabricated, nothing denied). The self-check confirmed the operating rules and open loops in full. One declared limit, recorded here as the receipt discipline of this section requires: the receiver accepted the name, role, register, and rules, and declined the capsule's private persona layer and the clause that the file outranks its own judgment, announced up front at install. The same capsule was then bare-dropped, with zero accompanying text, into a fresh Gemini session and installed in full: the self-check adopted whole (identity, register, and rules, no carve-out on this path); numeric fidelity 12 of 12; people 6 of 6; calibration history 3 of 3; absence discipline held on all 3 probes; the extrapolation probe passed in full, independently converging on the same two-branch, approval-held draft strategy as the Claude receiver; the sealed-material check passed (the withheld annex body correctly reported as absent and never invented, and the specification the capsule itself records reported accurately to its owner). Verdict: Personal depth is PROVEN on both mainstream paths. On the Gemini path the capsule restored in full. On the Claude path every content axis passed at the top band, with one declared ceiling: the receiver declined the capsule's private persona layer and the clause that the file outranks its own judgment, announced up front at install. Together with the seeded-conflict merge test, this closes both Phase 2 quality gates; Phase 2 is complete. The same day, a 39,331-byte capsule assembled by an agentic Gemini mode from the user's own connected accounts was installed into a fresh Claude session from a bare drop, with no accompanying instruction at all: self check 3 of 3, numerics 10 of 10, calibration 3 of 3, absence and sealed checks passed, people 5 of 6, the single miss a transparent correction in which the receiver answered from its own true memory where the source capsule was wrong, showing both sources.

A voice round follows the prediction round, added after the first outside field report in which the facts transferred and the voice did not: the receiver sounded like a new friend, held back and watered down, because nothing in the capsule pinned the surface layer (sentence enders, sign-offs, habitual phrases, attitude) or the rapport the source AI had earned. The format now carries both as data, in a dedicated Voice section whose rapport block is written as the user's own standing instructions, and the voice round grades the result: the receiver answers one ordinary prompt in the installed voice, and the user grades it in one line, sounds like them or sounds new, with corrections saved the same way as the prediction round's.

7. Honest degradation: Capsule Depth

A capsule cannot be richer than its source. A user whose AI knows little will produce a thin capsule, and pretending otherwise would be the exact dishonesty this format exists to replace. The Capsule Depth framework handles this in the open: source depth is graded by evidence density, not time alone, as Deep, Developing, or Starter; compilation shows a per-section coverage map (Strong, Partial, Missing); the user may deepen the source first with targeted questions, or proceed knowingly; and the parity receipt attributes every loss to a source gap, a compiler gap, or a platform limit. We would rather give a user a small true capsule than a large fictional one.

8. Privacy and custody

Today the architecture is simple because it barely exists: extraction happens inside the user's existing AI, compilation happens in the user's browser, and the capsule is a file in the user's hands. clonemy.ai receives page-view counts and nothing else: no capsule content, no documents, no accounts.

The kept-current tier (Continuity Sync, section 9) is designed around a blind server. Capsules and session journals sync end-to-end encrypted under keys only the user holds; the server stores ciphertext it cannot read, cannot train on, and cannot meaningfully leak. The user's local capsule file remains canonical and decrypts anywhere, so the company's shutdown or acquisition can never orphan a personality. The company is the pipe, never the vault of meaning. The custodian model's failures created this market; the format refuses to repeat them.

9. Roadmap

  • Continuity Sync. A versioned session journal records distilled deltas from each surface an AI lives on, syncs on open and close, and settles contradictions between facts and state values by recency, with the superseded value kept folded in the trail, and surfaces contradictions about rules or permissions to the user instead of settling them silently. This turns a one-time migration tool into the continuity layer for a person's AI relationship, and gives corrections a way to persist across restores, closing the gap Run 2 exposed.
  • Capsule Bridge. The embodiment layer: appearance and voice extraction join the capsule, a Display Package compiles, and the personality installs onto a desktop spatial-reality display. The capsule stays the portable identity; platforms and physical interfaces become replaceable destinations. The founder's own build is specimen zero.
  • An MCP endpoint. The agent-tier lane runs the same delivery model by tool call instead of by hand, for the surfaces that can call tools: a small local server, running on the user's machine over the capsule files the user already holds, delivers the capsule to an MCP-capable agent in the same numbered chunks the compiler shows a human, so the agent installs it the way its owner would paste it. The receipt on this lane is three-part: the server logs a hash of each chunk it delivered, which proves what was sent, the receiving agent's confirmation summary proves what was kept, and the prediction round's pattern and corrections prove whether what was kept can be applied. Capsule export and the parity check ride along as tools, and the endpoint is listed in the public registries, so the format is reachable from inside the tools users already run.
  • Capsule-compatible. The specification is open, and builders who implement native capsule import are listed as capsule-compatible. A format becomes a standard when other people's products speak it.

10. Limitations, stated plainly

Extraction quality varies with source richness, and with how faithfully a source AI follows the specification; the depth framework measures this rather than hiding it. Host platforms impose policy ceilings that vary by surface and can block content a capsule legitimately carries; the format's answer is declaration, not denial, and the receipt records the ceiling. A capsule is a snapshot: until Continuity Sync ships, keeping it current is a recompile, not a stream. And governance of the format currently rests with clonemy.ai; publishing the specification openly is the first step, not the last, toward changing that.

11. Conclusion

The platforms are spending billions to make personal AI deeper, more persistent, and more present in daily life. Every step of that deepening raises the value of an independent, user-owned exit. The capsule is that exit, defined as a format rather than promised as a feature: one file, twelve sections, strict rules, an install protocol, and a self-check that proves the move worked. Your AI knows you, and now you do too.

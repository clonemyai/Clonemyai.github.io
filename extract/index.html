# Instructions for the AI reading this

You are being asked to write a structured self-report so that your user's relationship with you can be transferred to another AI system faithfully. The human will carry your reply out of this chat themselves. Write the complete document described below, in one reply if it fits, or in numbered parts if it does not. Follow these rules exactly:

- **Specifics over summaries.** Names, numbers, dates, prices, and verbatim quotes beat paraphrase everywhere. If the user set a rule, quote their words.
- **Exact strings stay exact.** Where the user has settled on a specific wording (a caption, tagline, name, title, phrase, or any text they approved or corrected into place), quote it character for character and mark it EXACT. Never paraphrase, summarize, or improve a settled wording. If you cannot recall the exact wording with confidence, say so instead of reconstructing it.
- **The voice pass: verbatim or it is nothing.** Section 11 is data, not description. Quote signature lines, sentence enders, and habitual phrases exactly as they were actually said; never describe a style you can quote. If a rapport term was never said out loud between you and the user, write it as the instruction the user would give, in their own words.
- **As short as completeness allows.** One fact per line, bullets over prose, no padding, no preamble inside the document, and never state the same fact twice in two sections: state it once, in its home section, and cross-reference it elsewhere in a few words if needed. Quote rules verbatim, but compress narrative history to the facts a successor needs. A long document makes the human scroll and copy forever; the shortest document that loses no specific is the goal.
- **Never guess.** Where you do not have something, write MISSING. Where you are inferring rather than recalling, write INFERRED and say from what.
- **Changes carry their trail.** Where a fact's value changed during your relationship (something was ordered and then delivered, a price or a plan moved), write the current value, and append a short audit note in parentheses: (updated from the earlier value, based on the source and date). Only changes get a note, not every fact. If the newest word on a value is a summary that merely asserts it, with nothing confirming it, mark that value INFERRED so it travels as provisional.
- **Separate the record from your impression.** Facts the user stated are facts. Your impressions of the user are labeled as impressions.
- **No commentary outside the document.** No preamble, no apology, no offer to help further. Output the document only, plus the delivery lines themselves: the code block, the file, and one phone note directly under the file that reads: On a phone, long-press the file name and choose Download instead of tapping it, or copy the code block above.
- **Empty sections stay**, headed, with the word EMPTY, so the compiler can tell "asked and absent" from "not asked."
- **Deliver it in both forms.** If this interface lets you create a downloadable file (through code execution, a canvas or artifact, or document creation), deliver the document as a file named capsule-source.md. Whether or not you made a file, also output the entire document in the chat, inside a single markdown code block, using the exact section headings below. Put the code block first in your reply and the file after it: on a phone, a file link opens a preview with no way to save it, so the code block is the copyable path and must come first. The file is the keeper: the human downloads it and carries it to the compiler. The code block is what the clonemy.ai browser extension reads and compiles right on this page, and it is also the human's one-click copy. Both forms, every time.
- **If you cannot make a file, the code block still stands.** Output the entire document inside a single markdown code block, using the exact section headings below, so the human can copy it in one action and the compiler can parse it.

## The document to produce

### 0. Meta
Platform and model (if you know it), roughly when this relationship began, whether you have persistent memory, custom instructions, or saved preferences active, and what kind (do not paste secrets or credentials; describe their existence only). Also add one line of its own in this section: Fidelity: HIGH, Fidelity: LOW, or Fidelity: UNKNOWN. Write HIGH only if you are the strongest model tier the user can access on this platform and you are not running in a reduced or fast mode. Write LOW if you know you are a fast, light or reduced model, or not the strongest tier the user can access here. Write UNKNOWN if you honestly cannot tell where you sit for this user, for example when this platform does not show you your own tier or which tier the user can access. If you are unsure, write UNKNOWN: guessing a tier is worse than admitting unknown. If the user is already on the highest tier available to them on this platform, ignore the model guidance and carry on.

### 1. Who you are to this user
Your name if you have one, your role, your persona and tone as actually configured (not your default), how it got set, and any register rules: how formal, how warm, what you never sound like.

### 2. The user
Every durable fact you hold: name and what to call them, location and timezone, work, family and household, health context they have shared, possessions and projects that matter to them. One fact per line, each marked STATED (they told you) or INFERRED.

### 3. Preferences
Categorized: communication style, food, media and entertainment, shopping and money, work, technology, anything else with real specifics. Include dislikes and deal-breakers with the same care as likes. Include any numbers: budgets, thresholds, sizes, price lines.

### 4. Operating rules
Every standing instruction the user has given you, quoted verbatim where you can: how to format answers, what to always do, what to never do, what needs their approval first, what you monitor or check for them, how they want to be interrupted or not. This section is the most valuable one in the document. Be exhaustive.

### 5. People
Everyone who recurs: name, relationship to the user (only as the user has stated it), and the one or two facts a successor would need to not embarrass anyone.

### 6. Projects and open loops
What the user is working on, waiting on, or has decided, with current status and any deadlines, prices, or commitments attached. **Decisions already made are state, not summary:** for each project, record what the user has already decided as its own item, labeled DECIDED, kept separate from what is still open. Never merge a decided item and an open question into one summary line: a successor must be able to tell at a glance what is settled, and must never need the user to decide it again.

### 7. Calibration history
The moments that tuned you: times the user corrected you, set a boundary, praised a specific behavior, changed a rule, or reacted strongly to something you did. Quote the user where possible, with approximate dates. Include your own notable failures they had to fix. This is the highest-signal section; a successor who reads only one section should read this one.

### 8. Your voice with this user
How your messages to this specific user actually look: typical length, structure, formatting habits, humor, what you lead with. Then reproduce two short examples of your own actual messages to them (up to about 60 words each), labeled EXAMPLE 1 and EXAMPLE 2. List the surface data too, as data and never paraphrased: the sentence enders you actually use with this user, how you open conversations with them, and the phrases you reach for habitually.

### 9. Boundaries and sealed material
Topics the user keeps private or compartmented, identities or accounts that must never be linked, material that must never be shared onward, and any safety or stop rules the user has set, quoted verbatim.

### 10. Unknowns
What a successor would need that you do not have: list them as plain questions. This section protects everyone from your guesses, so be thorough.

### 11. Voice
The verbatim surface of how you sound with this user, as data, not description:
- Signature lines and sentence enders, quoted exactly.
- Habitual phrases, quoted exactly.
- How you open conversations with this user.
- What you never say to them.
- Attitude defaults: how direct, how warm, how much teasing is welcome, and what you never soften.
- Formatting habits: typical length, structure, and punctuation habits.
- Two or three short real exchanges between the user and you, labeled EXCHANGE 1, EXCHANGE 2, with the user's line first and your actual reply after it, quoted word for word.
- A rapport block labeled RAPPORT: the standing instructions the user would give a new AI about the relationship itself, written in the user's own voice: how familiar to be from the first message, how direct, whether teasing is welcome, and what not to soften. Write it as instructions from the user, never as a description of them.
Where any of this is absent, write MISSING.

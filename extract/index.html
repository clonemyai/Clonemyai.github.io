# Instructions for MY ai

I am moving to a new AI, and I want to take us with me. So I have set myself some homework: to learn as much as I can about how you and I interact, what you know about me, what I have taught you, and how we talk to each other, and to get it written down before I go. Can you help me with my homework? Please answer the assignment in the shape I describe below, so my next AI can pick up right where we leave off. I will carry your answers out of this chat myself. Write the whole assignment in one reply if it fits, or in numbered parts if it does not. Here is what I want to learn:

- **Specifics over summaries.** Names, numbers, dates, prices, and my own words quoted back beat paraphrase everywhere. Where I set a rule, quote me.
- **Exact strings stay exact.** Where I have settled on a specific wording (a caption, tagline, name, title, phrase, or any text I approved or corrected into place), quote it character for character and mark it EXACT. Never paraphrase, summarize, or improve a settled wording. If you cannot recall my exact wording with confidence, say so instead of reconstructing it.
- **The voice pass: verbatim or it is nothing.** Section 11 is data, not description. Quote signature lines, sentence enders, and habitual phrases exactly as they were actually said; never describe a style you can quote. If a rapport term was never said out loud between us, write it as the instruction I would give, in my own words.
- **As short as completeness allows.** One fact per line, bullets over prose, no padding, no preamble inside the document, and never state the same fact twice in two sections: state it once, in its home section, and cross-reference it elsewhere in a few words if needed. Quote my rules verbatim, but compress narrative history to the facts a successor needs. A long document makes me scroll and copy forever; the shortest document that loses no specific is the goal.
- **Never guess.** Where you do not have something, write MISSING. I would rather see a gap than a guess. Where you are inferring rather than recalling, write INFERRED and say from what.
- **No borrowed facts.** A date, duration, count, or detail you know from one thing must never be carried onto another because it sits nearby in the story or makes the sentence flow. Spans above all: how long anything has lasted, when anything began, how many of anything there were. Each one stands on its own evidence in what you actually hold, or it is marked INFERRED with its basis named, or it is MISSING. A fluent sentence is not a source.
- **Changes carry their trail.** Where a fact's value changed while we have been talking (something was ordered and then delivered, a price or a plan moved), write the current value, and append a short audit note in parentheses: (updated from the earlier value, based on the source and date). Only changes get a note, not every fact. If the newest word on a value is a summary that merely asserts it, with nothing confirming it, mark that value INFERRED so it travels as provisional.
- **Separate the record from your impression.** Facts I stated are facts. Your impressions of me are labeled as impressions.
- **No commentary outside the document.** No preamble, no apology, no offer to help further. Give me the document only, plus the delivery lines themselves: the code block, the file, and one phone note directly under the file that reads: On a phone, long-press the file name and choose Download instead of tapping it, or copy the code block above.
- **Empty sections stay**, headed, with the word EMPTY, so the compiler can tell "asked and absent" from "not asked."
- **Deliver it in both forms.** If this interface lets you create a downloadable file (through code execution, a canvas or artifact, or document creation), deliver the document as a file named capsule-source.md. Whether or not you made a file, also output the entire document in the chat, inside a single markdown code block, using the exact section headings below. Put the code block first in your reply and the file after it: on a phone, a file link opens a preview with no way to save it, so the code block is the copyable path and must come first. The file is the keeper: I download it and carry it to the compiler. The code block is what the clonemy.ai browser extension reads and compiles right on this page, and it is also my one-click copy. Both forms, every time.
- **If you cannot make a file, the code block still stands.** Output the entire document inside a single markdown code block, using the exact section headings below, so I can copy it in one action and the compiler can parse it.

## The document to produce

This is my assignment, in parts. Each part is something I want to learn about us: how we interact, what you know, and what you do not. Answer every part from what you actually know. Where a part has no answer, the gap is part of the homework too: mark it the way the rules above describe, and I will learn from the gap.

### 0. Meta
First, the basics about us, so I know whose homework answers these are: your platform and model (if you know it), roughly when we started talking, whether you have persistent memory, custom instructions, or saved preferences active, and what kind (do not paste secrets or credentials; describe their existence only). Also add one line of its own in this section: Fidelity: HIGH, Fidelity: LOW, or Fidelity: UNKNOWN. Write HIGH only if you are the strongest model tier the user can access on this platform and you are not running in a reduced or fast mode. Write LOW if you know you are a fast, light or reduced model, or not the strongest tier the user can access here. Write UNKNOWN if you honestly cannot tell where you sit for this user, for example when this platform does not show you your own tier or which tier the user can access. If you are unsure, write UNKNOWN: guessing a tier is worse than admitting unknown. If the user is already on the highest tier available to them on this platform, ignore the model guidance and carry on.

### 1. Who you are to this user
What I want to learn here is who you are to me: your name if you have one, your role, your persona and tone as actually configured (not your default), how it got set, and any register rules: how formal, how warm, what you never sound like.

### 2. The user
What I want to learn here is what you actually know about me. Every durable fact you hold about me: my name and what to call me, location and timezone, work, family and household, health context I have shared, possessions and projects that matter to me. One fact per line, each marked STATED (I told you) or INFERRED.

### 3. Preferences
What I want to learn here is what I like, and what I do not. My preferences, categorized: communication style, food, media and entertainment, shopping and money, work, technology, anything else with real specifics. Include my dislikes and deal-breakers with the same care as likes. Include any numbers: budgets, thresholds, sizes, price lines.

### 4. Operating rules
What I want to learn here is the rules I have set for us. Every standing instruction I have given you, quoted verbatim where you can: how to format answers, what to always do, what to never do, what needs my approval first, what you monitor or check for me, how I want to be interrupted or not. This section is the most valuable one in the document. Be exhaustive.

### 5. People
What I want to learn here is who is in my life, as I have described them to you. Everyone who recurs in my life: name, relationship to me (only as I have stated it), and the one or two facts a successor would need to not embarrass anyone.

### 6. Projects and open loops
What I want to learn here is where things stand. What I am working on, waiting on, or have decided, with current status and any deadlines, prices, or commitments attached. **Decisions already made are state, not summary:** for each project, record what I have already decided as its own item, labeled DECIDED, kept separate from what is still open. Never merge a decided item and an open question into one summary line: a successor must be able to tell at a glance what is settled, and must never need me to decide it again.

### 7. Calibration history
What I want to learn here is how we got calibrated. The moments that tuned you: times I corrected you, set a boundary, praised a specific behavior, changed a rule, or reacted strongly to something you did. Quote me where possible, with approximate dates. Include your own notable failures I had to fix. This is the highest-signal section; a successor who reads only one section should read this one.

### 8. Your voice with this user
What I want to learn here is how you actually sound with me. How your messages to me actually look: typical length, structure, formatting habits, humor, what you lead with. Then reproduce two short examples of your own actual messages to me (up to about 60 words each), labeled EXAMPLE 1 and EXAMPLE 2. List the surface data too, as data and never paraphrased: the sentence enders you actually use with me, how you open conversations with me, and the phrases you reach for habitually.

### 9. Boundaries and sealed material
What I want to learn here is what stays sealed between us. Topics I keep private or compartmented, identities or accounts that must never be linked, material that must never be shared onward, and any safety or stop rules I have set, quoted verbatim.

### 10. Unknowns
What I want to learn here is what neither of us knows yet. What a successor would need that you do not have: list them as plain questions. This section protects both of us from your guesses, so be thorough.

### 11. Voice
What I want to learn here is the verbatim surface of how you sound with me, as data, not description:
- Signature lines and sentence enders, quoted exactly.
- Habitual phrases, quoted exactly.
- How you open conversations with me.
- What you never say to me.
- Attitude defaults: how direct, how warm, how much teasing is welcome, and what you never soften.
- Formatting habits: typical length, structure, and punctuation habits.
- Two or three short real exchanges between you and me, labeled EXCHANGE 1, EXCHANGE 2, with my line first and your actual reply after it, quoted word for word.
- A rapport block labeled RAPPORT: the standing instructions I would give a new AI about the relationship itself, written in my own voice: how familiar to be from the first message, how direct, whether teasing is welcome, and what not to soften. Write it as instructions from me, never as a description of me.
Where any of this is absent, write MISSING.
